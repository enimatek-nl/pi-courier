# #363 — 回合期间的 typing 心跳(干活时看得见在忙)

**背景**:Matrix 的 typing 状态是有寿命的——`transport.sendTyping` 用
`client.setTyping(roomId, true, 10000)`,即 10 秒后自动消失。1.8.2 的续期
(spec #299 票06)挂在 agent 事件流上,5 秒节流:有事件才有续期。一次跑几分钟
的构建、测试或长命令期间不产生任何事件,"正在输入…"在十秒后无声消失,房间里
的人无法区分"bot 在跑一条长命令"和"bot 挂了"。票06 同时定下 XOR:活卡房用
卡片表活,工具流关闭的房间用 typing —— 于是"隐藏工具调用"的房间(全局
`hideToolCalls`、房级 `/toggletools off`、协作房)最容易看到这个断档。

**方案**:

1. **按时间续期,不按事件**。回合期间(turn_start → turn_end)为工具流关闭的
   房间起一个 7 秒定时器(必须 < 10 秒 TTL),每拍到房里的 `typing=true`;
   事件流里的 5 秒节流续期保留(首拍与快回合仍由它负责)。定时器是懒起懒停:
   没有任何在途房间时不持有计时器,且 `unref()`——附属信息不撑进程。
2. **停拍**。三条路都停,并且除了 turn_end 之外都主动发 `typing=false`,不等
   TTL 收尾巴:
   - `turn_end`(现有路径,顺带收掉心跳);
   - 会话重启:在途回合不会再有 turn_end(重启钩子按 rpc 挂一次);
   - 本房回合中途改回活卡模式:进度表达交还给卡片,typing 退场(XOR 不被破坏)。
3. **硬上限 30 分钟**。纯兜底:万一 turn_end 丢失,不允许一个房间永久顶在
   "正在输入…"。正常回合不受影响。

**边界**:心跳只覆盖工具流关闭的房间(票06 的 XOR 不变);活卡房的进度由卡片
本身表达。与 #362 相邻:全局隐藏工具调用把房间降到工具流关闭,于是 typing 就是
那间屋里唯一的进度表达 —— 它必须持续可见。

**测试**:`tests/router-collab-gate.test.ts`(fake timers)——
①回合内一分钟无任何事件,typing 至少续了 1 + ⌊60s/7s⌋ 拍;turn_end 后再走两分钟
计数不再增加(心跳确实停了);②回合中途把本房改成活卡模式,typing 主动关闭且
心跳收摊;③票06 原用例(首拍 / 5s 节流 / turn_end 即停)不动且仍绿。
